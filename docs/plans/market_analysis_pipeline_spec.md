# Pipeline Implementation Spec: market_analysis_pipeline_spec.md

## Introduction

The **Quantum Swarm Analysis Pipeline** is designed to provide a low-latency, deterministic, and context-rich data payload for automated trading agents. By fusing macro-environmental data, smart contract security checks, sentiment analysis, and strict technical indicators into a single concurrent feed, this pipeline eliminates conflicting signals and prevents API bottlenecks. The ultimate goal is to deliver a unified "Master Confidence Score" that dictates execution behavior and position sizing across the entire trading swarm.

---

## Layered Assessment Architecture

### Layer 1: Global Macro Environment

* Evaluates the overarching market conditions to determine if it is a "Risk-On" or "Risk-Off" environment.
* Analyzes macro indicators such as the VIX (Fear gauge), major stock indices, and forex rates.
* Acts as a global governor: if the macro environment is extremely Risk-Off, the pipeline flags the swarm to reduce overall position sizing.

### Layer 2: Security & Smart Contract Veto

* Queries security tools like TokenSniffer, RugDoc, and CertiK to check for critical risks.
* Verifies contract safety by checking for honeypots, hidden fees, and liquidity locks before a user or agent interacts.
* Acts as a hard veto: if a token fails these security checks, the pipeline immediately halts and returns a "DO_NOT_TRADE" signal.

### Layer 3: Market Sentiment Pulse

* Scans recent news and social posts for the target asset.
* Scores the emotional state of the market from -1 (Extremely Fearful) to +1 (Extremely Greedy).
* Identifies and summarizes key narrative drivers to provide contextual backing for price action.

### Layer 4: Technical Execution Triggers

* Fetches raw market data and computes technical indicators independent of the exchange.
* Calculates moving averages (MA7, MA25, MA99), RSI, MACD, and Bollinger Bands.
* Generates standardized trading signals ranging from `strong_buy` to `strong_sell`.
* Triggers a `strong_buy`, for example, if RSI < 30, MACD crosses positively, and the price touches the lower Bollinger band.

## Reference Logic

This optimized Python implementation uses `concurrent.futures` to execute the four layers in parallel, minimizing latency.

```python
import json
import concurrent.futures
from datetime import datetime, timezone

def calculate_swarm_action(security, macro, sentiment, technicals):
    """Synthesizes the 4 layers into a master recommendation."""
    
    if not security.get("is_safe", False):
        return {
            "action": "DO_NOT_TRADE",
            "confidence": 1.0,
            "max_portfolio_allocation_pct": 0.0,
            "reason": "Security clearance failed (potential honeypot/scam)."
        }
        
    tech_score_map = {"strong_buy": 1.0, "buy": 0.5, "neutral": 0.0, "sell": -0.5, "strong_sell": -1.0}
    tech_val = tech_score_map.get(technicals.get("signal", "neutral"), 0.0)
    
    sent_val = sentiment.get("score", 0.0) 
    macro_val = 0.5 if macro.get("status") == "Risk-On" else -0.5
    
    # Weighted Master Confidence: Technicals (50%), Sentiment (30%), Macro (20%)
    master_score = (tech_val * 0.5) + (sent_val * 0.3) + (macro_val * 0.2)
    
    action = "HOLD"
    allocation = 0.0
    
    if master_score > 0.6:
        action = "EXECUTE_LONG"
        allocation = 5.0 
    elif master_score > 0.2:
        action = "SCALE_IN_LONG"
        allocation = 2.0
    elif master_score < -0.6:
        action = "EXECUTE_SHORT" 
        allocation = 5.0
    elif master_score < -0.2:
        action = "SCALE_OUT"
        allocation = 2.0
        
    return {
        "action": action,
        "confidence": round(abs(master_score), 2),
        "max_portfolio_allocation_pct": allocation
    }

def generate_swarm_payload(symbol, contract_address=None):
    """Runs the 4-layer assessment concurrently and builds the JSON."""
    
    with concurrent.futures.ThreadPoolExecutor(max_workers=4) as executor:
        # Replace with actual SDK/API calls
        future_macro = executor.submit(fetch_macro_environment)
        future_security = executor.submit(check_security_clearance, symbol, contract_address)
        future_sentiment = executor.submit(analyze_sentiment, symbol)
        future_technicals = executor.submit(get_technical_signals, symbol)
        
        macro_data = future_macro.result()
        security_data = future_security.result()
        sentiment_data = future_sentiment.result()
        tech_data = future_technicals.result()

    recommendation = calculate_swarm_action(security_data, macro_data, sentiment_data, tech_data)

    payload = {
        "asset": symbol,
        "timestamp": datetime.now(timezone.utc).isoformat(),
        "global_macro_environment": macro_data,
        "security_clearance": security_data,
        "sentiment": sentiment_data,
        "technicals": tech_data,
        "swarm_recommendation": recommendation
    }
    
    return json.dumps(payload, indent=2)
```

## Agent Integration

Execution agents in the swarm are designed to parse the `swarm_recommendation` block of the JSON schema directly.

* **Action:** Directs the specific execution state (e.g., `EXECUTE_LONG`, `SCALE_OUT`, `DO_NOT_TRADE`).
* **Confidence:** The weighted master score calculated from the pipeline. Agents use this parameter to validate the statistical reliability of the signal before routing orders.
* **Max Portfolio Allocation Pct:** Acts as a hard ceiling for risk management, dynamically adjusting the trade size based on the macro weather and security veto logic.
